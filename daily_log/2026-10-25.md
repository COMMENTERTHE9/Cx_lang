## Landed today

### Literal type-checking and declared-type propagation (PRs #454, #457)

The interpreter and the JIT had been silently disagreeing on what a literal stored in a typed position held. A `t8` field initialized from a t32 variable holding 300 kept 300 on the interpreter but stored 44 (narrowed) on the JIT. PR #454 fixed the root: `insert_cast_if_needed` now converts each struct-literal field and array-literal element to the declared type, bringing both backends into agreement. PR #457 extended the declared-type propagation to every typed position — assignments, method arguments, if/when branches, nested arrays — and corrected several edge cases: a placeholder element type no longer counts as a declaration, `Ok` literals get range-checked, and widening is withdrawn so a declared type reaches only the value it annotates, not neighboring expressions. — **CONFIRMED** (commits `b20df09`, `8801783`, `87a69cb`, `2af5999`)

### Array element type enforcement (PR #461)

A language-level decision landed: arrays have one element type. Before this, `types_compatible` accepted any two numeric arrays of the same length as compatible, so `[3: t8]` went into a `[3: t64]` slot unconverted — the interpreter kept each value while compiled code read at the declared width, producing garbage like 67305985. Now, different element types are a type mismatch ("expected [3: t64], got [3: t8]"). Untyped array literals are typed by their first non-literal element. Two follow-up commits closed holes found by review: generic `T` elements are their own type (not a wildcard), forward calls check `.copy` types, nested generic literals are handled, and row variables are not silently narrowed. A compile-time regression was also fixed — nested generic calls at depth 20 dropped from 12.4s to 0.25s. — **CONFIRMED** (commits `7c5b32c`, `e3289e0`, `e6f263d`)

### Module naming by identity (PR #455)

Multi-module programs had four defects: a library couldn't call its own functions (renamed to `alias$name` but own calls kept the bare name), two aliases of one module only answered to the first, same-alias imports of different modules got duplicate symbols, and every file saw every alias. Modules are now keyed by `alias@id` with per-file import visibility. A follow-up commit added tests for generic struct imports, duplicate-alias rejection, library helpers vs. entry points, and phen-based cross-module calls. — **CONFIRMED** (commits `0eb248c`, `df65f1f`)

### Compound assignment operand checking (PR #456)

`x op= y` checked neither operand. Compound assignment on an enum, bool, unbounded generic `T`, or struct produced silent miscompilation: the interpreter kept full-width sums while the JIT wrapped, or the JIT did integer addition on a struct's address (SEGFAULT). `check_compound_operands` now applies the binary operator's rule. A second commit defers unknown-type targets to the run-time check, and a third refuses compound assignment on a generic struct's field. — **CONFIRMED** (commits `f5aae7a`, `6112249`, `2dce3ca`)

### JIT correctness fixes (PRs #458, #459)

PR #458 fixed two issues: a program with definitions but no top-level statements now runs as an empty program (not a failed compile), and enums with more than 256 variants are refused instead of wrapping the tag into 8 bits. PR #459 added branch-type checking to `if`/`when` value expressions — previously, an enum and a t8 sharing the I8 IR type, or two different structs sharing a pointer type, would compile one value as the other without a diagnostic. `lower_branch_value` now checks semantic types, not just IR types. — **CONFIRMED** (commits `e86eefa`, `6bb9fce`, `1ab0a2b`)

### Impl method scoping (PR #460)

An impl method's name now belongs to its type, not the global scope. Before, two structs each having a method named `add` was a name collision. — **CONFIRMED** (commit `163f051`)

### Float division safety (PR #452 — merged from yesterday's branch)

The `backend/float-div-by-zero` branch from yesterday merged to submain. Float division and compound `/=` `%=` now route through guarded emission, and t128 division/remainder is refused. — **CONFIRMED** (merge `c60465d`)

### Generic value conversion (branch-local, not yet merged)

Two commits on `backend/generic-value-conversion`. Generic bodies are checked once with `T` unknown, so a `T` value going into a `t8` slot had no cast: the interpreter kept the full-width value (300 in a t8) while compiled code narrowed or refused. `insert_cast_if_needed` now wraps `T` values in a cast to the declared number type. A second commit adds a unit test pinning the refusal of conversions between t128 and f64, which Cranelift cannot represent. — **CONFIRMED** (commits `4c38a54`, `5c969e8`)

## Decisions and direction

The day's work codifies several language-level decisions in code:

1. **Arrays have one element type.** This is now enforced at analysis time, closing a class of silent miscompilation where different-width arrays were treated as compatible. The decision is documented in `cx_syntax.md`.

2. **A declared type reaches only the value it annotates.** Widening — where a declared type leaked into neighboring expressions — has been withdrawn. Each typed position gets its own cast through `insert_cast_if_needed`, not through scope-level type inheritance.

3. **Modules are named by identity, not by alias.** The `alias@id` keying scheme makes multi-module programs sound: a library's own calls resolve, same-alias imports are distinct, and import visibility is per-file.

4. **Compound assignment uses the binary operator's type rule.** No separate, weaker rule for `+=`. If `+` refuses it, `+=` refuses it.

5. **Branch values must have compatible types.** The JIT no longer accepts an `if` or `when` expression whose branches produce different semantic types, even when they share an IR type.

The overarching theme is "the two backends must agree, and when they can't, the program is refused." Every one of today's 18 work commits closes a case where the interpreter and JIT silently produced different values, or where the JIT silently miscompiled.
