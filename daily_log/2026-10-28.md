## Decisions and direction

Several significant technical decisions crystallized today:

**Module state is identity-based, not name-based.** The binding identity model (`BindingId`) now governs module-state access, copy write-back targets, and const enforcement. This is a deliberate architectural choice: the runtime resolves targets by identity and capability rather than string name, preventing shadowing and aliasing bugs.

**Copy argument shapes are resolved at the IR level.** The new `call_shapes.rs` pass runs after monomorphization and before ABI planning — a new compiler phase. This means copy parameter shapes are concrete before any code generation decisions. The 64-shape-per-function limit is a deliberate cap.

**Enum module state uses nominal type checks.** Enum boundaries are checked before representation erasure, rejecting incompatible specializations before code generation. This matches the language's design philosophy of making type identity visible rather than structural.

**Dead code after returns is no longer emitted.** The lowering pass now tracks termination and stops emitting instructions after a return or break, cleaning up the IR.
