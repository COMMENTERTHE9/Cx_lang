## Decisions and direction

**Static string subset declared complete.** The D2.3d commit message states: "The static string subset is COMPLETE — only R6-deferred dynamic strings remain." This means the JIT now handles string literals, compile-time concatenation, content equality, and print-time interpolation. Any string operation requiring runtime allocation (dynamic concatenation with non-literal operands, runtime string construction) remains deferred to R6.

**Print-time vs build-time interpolation.** The interpolation strategy is explicitly print-time: the JIT decomposes `print("a {x} b")` into a sequence of inline prints rather than building a new string. This is a deliberate R6 avoidance — no dynamic string allocation needed. The approach works only for `print` statements; string interpolation in general expression context would require R6 infrastructure.

**Scope limitation filed, not fixed.** The flat binding map for interpolation is a known divergence from interpreter behavior. Rather than blocking D2.3d on a scope-threaded map, the limitation is documented in code comments and tied to the open interpolation-scoping question. This is consistent with the project's pattern of filing limitations explicitly rather than silently shipping incorrect behavior.
