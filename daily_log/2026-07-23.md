## Landed today

- **CONFIRMED** — `5093d78` on `submain` (Jul 22, 21:19 EDT): "feat(jit): lower phen method calls + bounded generics — static monomorphization (0.3.4 slice 5 of 6)." 122 insertions, 0 deletions, entirely in `src/ir/lower.rs`.

  This is the IR-lowering side of the gene/phen trait system. Phen methods now register in the signature table under the same `<ReceiverStruct>$<method>` mangling scheme as impl methods, and emit as monomorphized IrFunctions through `lower_semantic_function`. The ownership-locked rule guarantees no name collisions (one owner per method name per type, `$` never appears in user identifiers). Call sites resolve phen methods identically to impl methods — no dispatch table, pure static monomorphization as dictated by design decision 1.

  The commit deliberately guarded struct-returning and array-returning phen methods: struct-return was known unsound (callee returns a dangling pointer to its own dead frame), so unregistered methods caused call sites to SKIP cleanly (exit 127) rather than silently corrupt. This guard was lifted in the next commit.

- **CONFIRMED** — `07dd14d` on `submain` (Jul 23, 19:23 EDT): "fix(jit): struct returns via caller-allocated slot — free functions, impl methods, phen methods (live silent-corruption bug, zero prior coverage)." 272 insertions, 19 deletions across 10 files.

  **The bug:** Any function returning a struct by value — free function, impl method, or phen method — returned a `Ptr` to a callee-frame alloca. That frame is dead the moment the call returns, so the caller read garbage. Probed empirically: `make(13, 24)` printed `13` then `32758` on Cranelift (interpreter: `13`/`24`), exit 0, no error. This is the worst failure class the project tracks: silent wrong output with matching exit codes.

  **Why it wasn't caught:** Not one fixture in the entire verification corpus returned a struct from any function. The parity harness can only catch what the corpus exercises. Found only because the slice-5 ABI audit probed a method-struct-return before reusing the path — the bare-I128 lesson applied: enumerate what crosses a boundary, probe it, don't assume.

  **The fix:** `FunctionSignature` gains a `ret_struct: Option<String>` field identifying struct-returning functions. These receive a hidden trailing `$ret_slot: Ptr` parameter. Callers alloca the return slot in their own frame and pass its address. `emit_return_through_slot()` field-copies the result struct through the slot using the same Load/PtrOffset/Store idiom as struct-literal lowering. The slot pointer — not the dangling callee pointer — is returned. Nothing wider than a machine word crosses any boundary.

  The fix is applied in the shared `lower_semantic_function` path, so all three producer kinds (free functions, impl methods, phen methods) are covered by the single convention. Call-site lowering was updated to alloca the slot and adjust the user-arg count check to exclude the hidden parameter. The phen struct-return guard from slice 5 was lifted. Array returns remain guarded (same dangling-frame shape, slot convention not built for array layouts).

  **New regression fixtures:**
  - `t_struct_return_free` — the exact 13/32758 reproduction case, now asserting 13/24.
  - `t_struct_return_impl` — same proof through the impl-method path.
  - `t_struct_return_double_free` — two calls, asymmetric inputs, both independently correct (no slot-reuse contamination).
  - `t_struct_return_double_method` — same double-call proof through impl methods.

  **Known issues entry:** `docs/known_issues.md` #10 documents the full bug, root cause, coverage gap, fix convention, and remaining follow-up (array returns).

## Decisions and direction

1. **Caller-allocated return slot as the struct-return convention.** Rather than fixing each function kind independently, the fix was placed in the shared `lower_semantic_function` path with a single convention: hidden trailing `$ret_slot: Ptr` parameter, field-wise copy at return sites, caller-frame alloca at call sites. This makes the convention uniform and ensures any future function kind using the shared path gets correct struct returns automatically.

2. **Array returns remain guarded, not fixed.** The same dangling-frame shape applies to array returns, but the slot convention was only built for struct layouts (which have per-field offset tables). Array-return support is a tracked follow-up. Unregistered methods continue to SKIP cleanly rather than corrupt — a deliberate safety choice.

3. **Phen method monomorphization is static, no dispatch table.** Slice 5 confirms design decision 1 from the gene/phen design pass: phen methods are compiled as direct-call monomorphized specializations, not through vtable dispatch. Each gene/type combination produces one named function.

4. **The "probe before reusing" discipline continues to pay off.** The struct-return bug was found by systematically probing every shape that crosses a function boundary during the ABI audit step of slice 5. This is the same discipline that found the bare-I128 issue earlier. The project's `docs/known_issues.md` now documents 10 numbered issues, all found through systematic probing rather than user reports.
