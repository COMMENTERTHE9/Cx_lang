## Decisions and direction

**Enforcement-layer principle locked.** This is the project's second locked design principle (after the method-ownership principle in `gene_phen_design.md`). The rule emerged from a pattern across six prior bug fixes (f64 comparison, enum equality, width checks, ordering allowlist, const immutability, and now C1-C4) where the same structural mistake — checking at construction but not access — produced invisible divergences between the two backends. The parity harness cannot see these because `TestExpectation::Fail` is satisfied by any non-zero exit, and the JIT's exit-127 trap counts as a clean SKIP. The principle closes the class of bugs rather than patching individual instances.

**C2 bypass disposition recorded explicitly.** The audit found that the interpreter has by-name write paths (`read()`, `input()`, multi-alias method write-back) that bypass `Stmt::Assign` and could theoretically write to a loop counter. These are currently unreachable because the counter is typed `t64` and the bypass paths carry `str` or struct payloads — a type mismatch in a different layer. The commit records this as a latent hole that becomes reachable if loop counters ever gain non-t64 types, with an explicit instruction that whoever makes that change must add the runtime guard in the same commit.

**Three new known issues filed (not fixed).** #15 (constant-index OOB / literal-zero division), #16 (runtime-checked string interpolation), and #17 (diagnostics: hardcoded pos:0 and wrong-operator messages) are all documented as open. None block release but they are concrete follow-up targets.
