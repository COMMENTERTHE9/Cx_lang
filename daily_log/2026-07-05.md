## Landed today

**CONFIRMED — `3ea986d` (submain): Handle.drop lowered — D2.5c, closes the scalar Handle core arc**

`cx_handle_drop(handle: i64) -> void` calls the registry's `remove()`, which checks `slot.gen != handle.gen` and returns early on mismatch — making double-drop non-corrupting by construction, not by new logic. The expression result is the pre-call packed handle i64, unchanged; HandleDrop's semantic type (`Handle(I128)`) is protected by the same T-blind `lower_type` collapse as HandleNew.

The stale-handle Trap proof deferred since D2.5b now fires: `t_handle_stale_trap` constructs, drops, then forces `.val` via `assert_eq`. Both backends reject deterministically (interp exit 1, JIT exit 126 via `cx_trap`). `t_handle_generational_reuse` mirrors the registry's own unit test — drop h1, construct h2 on the freed slot, confirm h2 reads correctly while h1's stale `.val` rejects. `t_handle_double_drop_no_alias` proves non-aliasing specifically: drop the same handle twice, construct two new handles, confirm each reads its own distinct value (free-list corruption would cause aliasing).

Files: `src/ir/lower.rs` (+38/-1), `src/backend/cranelift/host_boundary.rs` (+43). Three new fixtures. Matrix on submain: 300/0 per commit gates.

**CONFIRMED — `e7bf778` (submain): `as v` binding on `when` EnumVariant arms — first pattern matching slice**

Full-stack implementation across lexer (`KeywordAs`), parser (optional `as ident` after `EnumName::Variant`), semantic analyzer (arm-scoped binding declared as the enum's own type), IR lowering (SSA alias — scrutinee value inserted into the arm body block's incoming bindings), and interpreter (`declare` + `set_var_by_id` in the arm scope). Enums are tag-only in Cx, so "binding the whole scrutinee" is the only meaningful `as v` semantics — there are no fields to destructure.

The `WhenPattern::EnumVariant` tuple grew from 2 to 3 fields (`Option<String>` for the binding name). `SemanticWhenPattern::EnumVariant` gained a `binding: Option<(BindingId, String)>` field. Both `analyze_when_pattern` and a new `analyze_when_pattern_scoped` handle the two paths. Both `lower_when_stmt` and `lower_when_expr` got the same SSA-alias insertion.

Ten new test fixtures: 2 positive (`t_pattern_as_binding_discriminate` — nested `when` on `v` proves correct arm binding; `t_pattern_as_binding_catchall_fallback`), 8 negative (reject `as v` on literal, range, catchall patterns; reject duplicate binding name; reject scope leak to other arms and outer scope).

Files: 24 files changed, 202 insertions, 9 deletions.

## Decisions and direction

**The scalar Handle arc (D2.5) is closed.** Construct, read, and drop for scalar `Handle<T>` are complete on both backends with empirical safety proofs. The commit message explicitly marks what remains deferred: non-scalar `Handle<T>` (str, struct payloads), nested `Handle<Handle<T>>`, and t16 (blocked by two unrelated pre-existing gaps).

**Pattern matching has started.** The `as v` binding on `when` EnumVariant arms is scoped as the first slice of 0.3.2. The implementation chose whole-scrutinee binding (not destructuring) because Cx enums are tag-only — this is correct by construction, not a shortcut. Guard clauses are the next piece of 0.3.2 scope per the roadmap.

**The roadmap is now a living document with real version targets.** Prior to `10ac2ed`, no committed file contained a version sequence past 0.1. The reconciliation records what was always the intended direction but never formally written down, and it corrects two items (NullPoint, random) from "pending implementation" to "genuinely undesigned" based on 0.3-cycle audit results.
