**Slice 1 — .copy semantic settlement** (`aa76b68`, 18:09) — CONFIRMED
Four language rulings settled at choke points, zero fixture conversions by design. This was the foundation beneath the ABI work:
- **Repeated `.copy` targets rejected.** `f(x.copy, x.copy, x.copy)` gave nondeterministic output — three different answers in ten runs — because bleed-back order depended on `HashMap` iteration. Now a semantic error. Ten runs, one answer.
- **`copy_into` bundles enforced at analysis time**, closing a layer violation where a static name mismatch was a runtime error.
- **`.copy` on method parameters rejected** (Option B) at both argument and declaration. `call_semantic_method` never registered a bleed-back, so `.copy` there was silently inert. No fixture or example ever used it.
- **Array `.copy` parsing fixed.** The parser discarded the declared type from `n.copy: T` because `ParamKind::Copy` had no slot for it. Now carries `Option<Type>`, so `f(r.copy: [3: t64])` works and writes back correctly.
- **`freed` removed** — a `HashSet` that was never inserted into, leftover from `free_variable` (removed March 2026). Its printer was worse than dead: it printed "= freed" for every live variable at every scope close.
- **`.copy.free` deprecated** with accept-and-warn. Its `free` suffix names an operation removed five months ago.

Two choke points, not scattered arms: `check_copy_arg_contract` (one call per call site, three argument rules) and `analyze_function` with a required `is_method` flag.

**Slice 2 — .copy ABI implementation** (`005df8c`, 19:19) — CONFIRMED
ABI option (a): `.copy` parameters pass by address uniformly for every type. The caller allocates a slot, copies contents in, passes the address, and reloads after the call. The callee receives a `Ptr`, copies to a local on entry, and writes back through the same address at every exit via `finish_return`. Scalar and aggregate differ only in how contents move (load/store vs. `ret_slot_plan` parts).

Key results:
- `t49_copy_contract` converted from SKIP to PASS — the one fixture this was designed to close.

## Decisions and direction

Three design decisions were made today, all arising from the `.copy` lowering work:

1. **ABI option (a) — uniform by-address passing for `.copy`.** Scalars and aggregates are no longer separate semantic cases; both pass through a caller-allocated slot. This is the simplest design, and cost on non-`.copy` parameters is proven zero.

2. **Argument-parameter kind agreement enforced.** A `.copy` argument against a plain parameter (or vice versa) is now a semantic error. This was forced by the ABI — a callee cannot have two calling conventions depending on how it's called — and surfaces a divergence that had been undiagnosed. The interpreter wrote back in one case and not the other; the JIT did the reverse. Both now agree because mismatches are rejected.

3. **Function-body `const` reclassified.** The roadmap re-freeze corrected a mis-categorisation: `const k: t64 = 5` inside a function body is a parse error on both backends, so it's not a lowering blocker — it's unimplemented syntax belonging to language surface work.

The roadmap on `submain` now carries a detailed `.copy` / `copy_into` sub-section with five numbered rulings, their landed/pending status, and an explicit statement that the blocker is still not fully closed.
