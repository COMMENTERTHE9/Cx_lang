## Landed today

### Generic local interpreter fix (`backend/generic-local-interpreter-fix`, commit `543dc9d`) — CONFIRMED

A local declared with a type parameter (`y: T = x` inside a generic function) now takes the type of its value on the interpreter. Previously, the interpreter had no case for a type parameter in its declared-variable-type check, so every generic function that declared a local of type `T` stopped with a type mismatch — while compiled code, which specializes per type, ran it correctly. This was the §72i bug identified by yesterday's review cycle.

The fix is in `src/runtime/scope.rs`. The scope system was substantially refactored: `push_function_scope` now takes a name map, bleed-back tracking switched from name-based to `BindingId`-based, and the debug-scope infrastructure was simplified. Five new test fixtures cover scalar types, enum/struct/array, Result, char/handle/unknown, and a negative case confirming that reassigning a `T` local to a value of a different kind is still rejected.

### Value and alias semantics amendment (`backend/value-alias-semantics`, commit `f40aec1`) — CONFIRMED

A proposed design document (`docs/backend/cx_value_and_alias_semantics.md`) formalizes the owner's 2026-11-19 decision: value semantics by default, with mutation through explicitly defined mechanisms. The document establishes rules V1 through V4+ covering values, receivers, operator operands, `.copy`, and the one-variable-one-receiver constraint. It amends `docs/backend/cx_eval_order.md` and resolves every open case of known-issues §69.

This is a design document only — no code implements it yet. It is under independent review.

Two commits: one adds Windows CI jobs mirroring the existing Linux gates (`d97e03c`, 58 lines to `.github/workflows/ci.yml`), and one creates a register of legal programs that compiled code refuses since submain (`61b50b5`, `docs/backend/compiled_code_refusals.md`).

The CI change adds two new jobs on `windows-latest`: "Windows Frontend Build + Matrix" (cargo build + run_matrix.sh under Git Bash) and "Windows Backend Build + Tests" (cargo build --features jit + cargo test --features jit). The push trigger already covers `backend/**` branches, so these run automatically. The language is developed on Windows as well as Linux, but until now nothing in CI exercised that.

The refusals register documents every compiled-code refusal introduced by the November 2026 correctness work: 8 regressions (R1–R8) where submain compiled and got right but the code now refuses, 4 defect replacements (D1–D4) where the refusal replaced a wrong answer or crash, and 18 fixtures that pin these outcomes. Each entry states what lifts it.

### Result type analysis (`backend/result-type-analysis`, commit `61915fb`) — CONFIRMED

The `result_payload_compatible` rule is now enforced in semantic analysis (`src/frontend/semantic.rs`): where a `Result<T>` is declared, a Result may be used if its payload type is `T`, or nothing (an `Err`), or a whole number no wider than `T`. Anything else — including `Ok` of a known type into `Result<unknown>` — is a type mismatch. This implements the owner's 2026-11-19 decision that assigning a Result to an incompatible or narrower declared Result payload type is an analysis error, not a backend refusal.

The commit also restructures the semantic analyzer substantially: `VarInfo` gains `is_function`, `is_method`, and `function_key` fields; a new `IdCounters` struct ensures binding/function/enum/variant ids are unique across modules; `const_names` becomes `const_bindings` keyed by `BindingId`; and module aliases now carry their module key. These are infrastructure changes that the result-type rule needs or that were cleaned up alongside it.

Fifteen new test fixtures: 10 `expected_fail` cases (narrowed declarations, parameter passing, returns, arithmetic, copy, array element, whole-number-as-float, untyped number) and 5 `expected_output` cases (payload types that fit, small constants at narrow types, value branches with Err).

Changes to `src/ir/lower.rs` and `docs/known_issues.md` accompany the semantic changes.

## Decisions and direction

Three of yesterday's seven requested owner decisions now have concrete implementations or proposals:

1. **§72i — generic local interpreter bug** → Fixed by `543dc9d`. The interpreter no longer fails on a local declared with a type parameter. This was decision item #5 from yesterday.

2. **§7.3 — Result narrowing as analysis error** → Implemented by `61915fb`. Assigning a Result to an incompatible or narrower declared type is now a type error caught in analysis, not a backend refusal. This was decision item #3 from yesterday.

3. **§7.2 — operands and aliases: values or references?** → Formalized in the value/alias semantics amendment (`f40aec1`). The proposed answer: everything is a value except aggregate receivers, which are the variable itself when bound to a named variable. Operator operands are always values. This was decision item #2 from yesterday.

The remaining four decisions from yesterday's list — interpreter behavior changes (item #1), new refusal acceptability (item #4), PR #476 closure (item #6), and PR creation order (item #7) — are not directly addressed by today's commits.
