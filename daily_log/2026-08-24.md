## Landed today

**1. Model A — contiguous multidimensional arrays, one owned value** (`332a46a`, submain, 21:25 Aug 23) — CONFIRMED

The single commit today, but it's a large one: 764 insertions, 117 deletions across 23 files. Nested arrays (`[R: [C: T]]`) become one contiguous, row-major allocation. The conversion is structural rather than incremental — `ret_slot_plan` in `src/ir/lower.rs` is now recursive, so `Array(3, Array(4, I32))` produces 48 bytes with twelve `(offset, I32)` parts instead of three pointers. Every consumer that already read the plan — bind copy, parameter entry copy, return slot, aggregate stores — gets deep copy for free without a deep-copy walker existing anywhere.

Key implementation details from the diff:

- **Parser** (`src/frontend/parser.rs`): the index rule changed from `.or_not()` to `.repeated()` with a left fold. `a:[i]:[j]` folds into `Index(Index(a, i), j)`. The write side (`index_assign`) mirrors this exactly. Minimal syntax change — types and literals were already recursive.

- **IR types** (`src/ir/types.rs`): `compute_struct_layout` renamed to `compute_struct_layout_from_sizes`, now taking `(size, align)` pairs directly instead of `IrType` values. This is because under Model A, an aggregate field is stored inline — its size is the full aggregate's storage, not the 8 bytes a `Ptr` would occupy.

- **IR lowering** (`src/ir/lower.rs`): new `slot_size_align` and `elem_stride` functions enforce the single-authority rule. `elem_stride` is THE stride — `ret_slot_plan` lays out parts with it, `resolve_array_element_ptr` does index arithmetic with it, and `index_stride_and_copy_plan_agree` asserts they cannot disagree. 441 lines of changes in this file alone.

- **Runtime** (`src/runtime/exec.rs`, `src/runtime/scope.rs`): interpreter-side changes to match the contiguous storage model.

The three aliasing divergences are closed as a structural consequence, not individual patches:
- `a:[0] = n` then `n:[0] = 5` — was 77/5, now 77 both
- `h.arr = n` then `n:[0] = 5` — was 77/5, now 77 both
- `arr:[0] = x` then `x.v = 99` — was 11/99, now 11 both

Under contiguous storage, a slot has no pointer to overwrite, so the alias literally cannot be formed.

## Decisions and direction

Today's commit embeds a major architectural decision: **Cx multidimensional arrays are contiguous and flat.** A `[3: [4: t64]]` is one 96-byte allocation with twelve 8-byte elements at row-major strides — not a container of three pointers to independently allocated 4-element rows. This means:

1. The value-semantics model (Model B, landed Aug 23) composes cleanly — a bind copies the flat storage, so there are no dangling interior pointers and no need for a deep-copy walker.
2. The three aggregate-aliasing divergences close as a structural consequence. There is no pointer to alias because there is no pointer — only offsets into contiguous storage.
3. The 0.5 roadmap delivery item ("Multidimensional arrays landed, or actively completing") is substantially complete. What remains of the design gate is deliverable 6 (whether rank 4 falls out of the general case — rank 3 already works) and the write-side grammar limitations.

The roadmap's design gate was structured as six ordered deliverables before any code. Model A's approach was different: build the contiguous model, prove it works up to rank 3, and let the implementation settle the design questions that the gate was meant to resolve. The `:` collision (deliverable 1) is moot for reads — `a:[i]:[j]` works — and partially moot for writes at the top level. Type syntax, indexing syntax, literal syntax, and memory layout (deliverables 2-5) are all settled by the implementation. Deliverable 6 (rank 4 / N-dimensional generality) is the remaining open question.

The `docment/ROADMAP.md` on submain was updated in this commit to reflect Model A's impact on the design gate and the remaining lowering blockers. The `docs/known_issues.md` gained a new §28 documenting the model and its remaining parse limitations.
