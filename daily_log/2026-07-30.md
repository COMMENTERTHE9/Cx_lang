## Landed today

**Harness rejection-shape tracking** (`1f92b39`, submain) — CONFIRMED

The `.expected_fail` sidecar previously asserted only `exit_code != 0`. A JIT hard trap (exit 126) satisfied a fixture whose interpreter emits a clean line-numbered diagnostic (exit 1) — the harness could not distinguish "both diagnosed it" from "one diagnosed it and the other crashed." This was the blind spot where every C5/C6-class divergence hid.

The fix introduces `RejectionShape` (Diagnostic = exit 1, Trap = exit 126) and a `#!` directive syntax in `.expected_fail` files:

```
#! interp=diagnostic jit=trap
```

Key details from the code and commit:
- A survey of all 137 `.expected_fail` fixtures found the interpreter's error KIND predicts the exit pair exactly, with no exceptions. Parse/resolve/semantic errors give (1,1) because they fire before backend dispatch. Every runtime error gives (1,126) — the JIT funnels fifteen distinct interpreter diagnostics through one `cx_trap` channel.
- 18 fixtures legitimately carry `jit=trap`. The remaining 119 default to `interp=diagnostic jit=diagnostic` when the marker is empty.
- Both directions are now caught: a `jit=diagnostic` fixture that starts trapping, and a `jit=trap` one that stops.
- A typo in a directive panics rather than falling back to the default, which would silently re-open the hole.

The same commit also promotes `.expected_exit` to a first-class sidecar in the Rust harness. Previously `run_matrix.sh` honoured it but `collect_matrix_tests` had no branch for it — the five exit() fixtures were classified from their `.expected_fail` companion and their designed exit codes (3, 4, 5, 7, 9) went unasserted on both backends. Now highest sidecar priority, matching the shell runner's order.

Four new unit tests added (`cargo test` 246 -> 250, with `--features jit` 421 -> 425). Parity unchanged: 345/51/0. Matrix 396/0. No behavior change — pure metrology improvement.

**Enforcement layers design doc + known-issues update** (`a33f9b0`, submain) — CONFIRMED

`docs/frontend/enforcement_layers.md` is a new 169-line document locking the enforcement-layer principle: "If a fact is known to semantic analysis, semantic analysis rejects it. Any surviving backend check is defense-in-depth only." Two corollaries: a backend check is never the only check; a check only speaks where the fact is actually known. This is now a design principle with the same standing as the method-ownership principle.

The document records where the principle came from (the six holes found in one session, the four-in-one access-path audit), how to apply it when writing new checks (single choke point, not per-syntactic-form arms), and how to decide whether to keep or remove an existing backend check. It also records the known limits: position-zero diagnostics, statically-decidable cases still at runtime, the JIT's single trap channel.

`docs/known_issues.md` §15 updated: the harness half is marked resolved — the survey table, why forbidding the (1,126) pair would have flagged the JIT's designed runtime-error channel rather than 18 divergences, what the annotation asserts, and how to enumerate the 18. Two things are marked explicitly open: the language half of C5/C6, and giving the JIT real per-error diagnostics (which would collapse the 18 to (1,1)).

## Decisions and direction

The enforcement-layer principle is now formally locked as a design document. This is the first time the "analysis rejects what analysis knows" rule has been elevated from a pattern observed across the C1-C4 fixes to a stated architectural principle with the same standing as the gene/phen method-ownership rule.

The harness work represents a decision about the JIT's single trap channel: the 18 fixtures that legitimately differ are *recorded and asserted* rather than forbidden. Forbidding them would have flagged the JIT's designed runtime-error path. The residual — giving the JIT real per-error diagnostics — is explicitly deferred and documented as future work that would collapse the 18 to (1,1) and let a strict same-shape rule land for free.
