- **Dispatch strategy** (item 1): DECIDED — static monomorphization only for 0.3.4. No dynamic dispatch in this release. Every concrete gene/type combination compiles to a specialized implementation. Dynamic dispatch deferred until a concrete use case justifies designing trait-object semantics properly.
- **Operator gene mapping** (item 4): DECIDED for Ord — four separate methods (`lt`, `gt`, `le`, `ge`) mapping directly to `<`, `>`, `<=`, `>=`. No `cmp`/`Ordering`-result-type convenience in 0.3.4. The design preserves room for a future `cmp` method without breaking existing implementations.
- **Built-in gene provenance** (item 6): DECIDED — prelude source is the canonical, permanent architecture for operator genes (`Add`, `Sub`, `Mul`, `Div`, `Eq`, `Ord`, etc.). For 0.3.4 bootstrapping, the compiler may use narrowly-scoped primitive intrinsics under five hard constraints ensuring they're temporary and conformant, not a permanent parallel system.

**docs: record gene/phen decisions — Self resolution, phen lookup, narrow coherence** (`2f18e20`, 21:12 EDT, submain) — CONFIRMED. Resolved two more items and narrowed a third:

- **Phen lookup** (item 2): DECIDED — forward-reference capable via a semantic pre-pass that registers phen headers before method-call/operator/bound resolution. Mirrors the existing struct/enum/function pre-pass pattern. Source order never determines whether a valid implementation exists.
- **Self resolution** (item 3): DECIDED — `Self` resolves throughout the entire `phen` body as a compile-time alias for the concrete implementing type, substituted during semantic analysis using the existing type-substitution machinery. This was previously the single "A2" blocker flagged in every prior status check.

## Decisions and direction

Today's work is almost entirely about design decisions, and the decisions are consequential. The gene/phen implementation questions were originally scoped as the "A1/A2 sprint" — a prerequisite gate before the 0.3.3 design-verification pass could begin in earnest. With 5 of 6 now resolved, the path from 0.3.3 (design verification) to 0.3.4 (implementation) is substantially clearer.

Three decisions are worth calling out for their downstream implications:

**Static monomorphization only** means 0.3.4 avoids the design complexity of trait objects, object-safety rules, and vtable ABI — a significant scope reduction that keeps the initial gene/phen implementation focused. Dynamic dispatch is explicitly not rejected, just deferred.

**Prelude-first with bootstrap intrinsics** is the most architecturally significant decision. It commits to operator genes being real Cx source, not compiler magic, while pragmatically allowing temporary shortcuts for primitive types during bootstrapping. The five constraints on the bootstrap path are strict enough that they define their own removal criteria.

**Self resolution throughout the phen body** resolves the one item that was consistently flagged as the blocker. The decision to use existing type-substitution machinery (the same path as generic-struct type-parameter substitution) means no new infrastructure is needed — it's a configuration of what already exists.

The submain branch continues to grow without merging to main. It's now been 12 commits and three consecutive daily-log predictions of an imminent merge that hasn't happened. The branch appears to be used as a long-running integration branch where correctness fixes and design work accumulate, with main reserved for tagged releases.
