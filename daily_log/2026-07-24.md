  This is the capstone commit of the gene/phen sprint. It introduces:

  **The embedded prelude** (`src/prelude.cx`): a 52-line real Cx source file defining the eight canonical operator gene contracts — `Add`, `Sub`, `Mul`, `Div`, `Mod`, `Neg`, `Eq`, `Ord`. The file is compiled into `cx.exe` via `include_str!` and injected as the first source unit of every program, before the root file and all imports, through the ordinary lexer-parser-semantic pipeline. No filesystem probing, no fallback — the embedded text is the sole runtime path. This is decision 6 from the design doc: the prelude is the canonical, permanent architecture, not a hardcoded second system.

  **Operator-gene dispatch** (`src/frontend/semantic.rs`, ~240 insertions): the new `try_operator_gene_dispatch()` method handles all binary operators (`+`, `-`, `*`, `/`, `%`, `==`, `!=`, `<`, `>`, `<=`, `>=`) and unary `-`. When the left operand is a user struct with a phen for the corresponding gene, the operator is rewritten to the same `MethodCall` node a hand-written `a.add(b)` produces — reusing the proven slice 3/5 dispatch machinery with no new dispatch mechanism. `!=` is derived as the logical NOT of `eq()`, matching the Eq gene contract. Types without a phen fall through to the existing built-in paths unchanged.

  **Prelude injection and collision detection** (`src/frontend/resolver.rs`): the resolver now injects the prelude as module ID 0, before all other source units. Gene duplicate detection gained source-location tracking — a user redeclaring a prelude gene gets an error naming `<prelude>:LINE`, using the same collision machinery as every other declaration kind.

  **Interim restriction**: operator dispatch requires a named variable as the left operand (expression receivers like `(v1 + v2) + v3` produce a clean error). This is a known gap that lifts when method receivers become expressions, tracked for 0.3.3.

  **Design doc update** (`docs/post_0_1/gene_phen_design.md`): 34 lines documenting the prelude architecture, embedding strategy, injection order, bootstrap intrinsic gap, and the interim restriction.

## Decisions and direction

1. **The prelude is the permanent architecture for operator contracts.** Decision 6 from the gene/phen design doc is now implemented: `src/prelude.cx` is the single source of truth, embedded at build time, injected through the standard pipeline. There is no hardcoded operator-overloading syntax and no second system. This is a permanent architectural choice, not a stopgap.

2. **Bootstrap intrinsics bridge primitives until they carry real phens.** The built-in numeric paths in semantic analysis (addition, subtraction, comparison, etc.) now explicitly conform to the prelude gene contracts and are marked as bootstrap intrinsics at their sites. They are designed for removal. Known gap: primitives do not yet satisfy `T: Add`-style generic bounds, since bound checks consult the phen registry and intrinsics are not registry entries.

3. **0.3.2 shipped as a release.** The version sequence in the roadmap was updated to reflect what actually shipped: 0.3.1 included pattern matching (originally planned for 0.3.2), and 0.3.2 contains gene/phen, operator overloading, generic bounds, the struct-return fix, and audit hardening. 0.3.3 is next with array-return lowering, generic-function lowering, and expression receivers.

4. **The interim expression-receiver restriction is accepted and tracked.** Operator dispatch requires a named variable left operand. This is explicitly not a design position — it's an implementation gap that lifts when method receivers become expressions. It's scoped for 0.3.3.
