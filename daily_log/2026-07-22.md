  - `FunctionInfo` carries `type_bounds` alongside `type_params`, stamped by the FuncDef analysis arm after `analyze_function` returns.

  - `Analyzer` gains three new fields: `gene_defs` (whole-graph gene signatures from Pass 0), `phen_keys` (set of `(gene, receiver_type)` pairs proving a phen exists), and `current_type_bounds` (the enclosing function's bounds, saved/restored around each FuncDef analysis).

  - **Gene-method resolution on bounded type params:** When a method call's receiver has type `TypeParam(T)` and `T` carries bounds, the analyzer looks up each bound gene's contract in `gene_defs`, finds the method signature, substitutes `Self -> TypeParam(T)` to keep the return type generic, and type-checks the call against the gene's declared parameter and return types. If no bound provides the method, a targeted error names the type parameter, the method, and the missing bound.

  - **Instantiation-site bound satisfaction:** When a generic function is called with concrete type arguments, each `(param, bound_genes)` pair is checked — the concrete type must have a phen for every bound gene in `phen_keys`. Failure produces a diagnostic naming the type, the bound, the function, and the missing phen. This is the gate that ensures you can't call `run_it<Compute>(plain, 5)` if `Plain` has no `phen Compute`.

  - **GenePhenRegistry expanded:** The Pass 0 registry now exports `genes` and `phen_keys` alongside the existing `phen_methods`, and injects all three into every per-file Analyzer.

  - **TypeParam resolution fix:** The method-call path now resolves the receiver's declared type against the enclosing function's type params (`current_type_params`) instead of `&[]`, so a `t: T` parameter surfaces as `TypeParam("T")` rather than being misread as an unknown struct named "T".

## Decisions and direction

1. **Bounds grant access, not runtime types.** The `t_gene_bound_unbounded_reject` fixture codifies a significant design choice: even if a concrete type has the right phen, calling a gene method on an unbounded type parameter is a semantic error. This means bounded generics in Cx are opt-in contracts, not just optimization hints. The bound is a static proof obligation.

2. **Self substitution stays concrete, also in bounds.** Gene signatures carry `Self` as `TypeParam("Self")`. When resolving a gene-method call on a bounded `T`, the analyzer substitutes `Self -> TypeParam(T)`, keeping the return type parametric within the generic body. This is consistent with the slice 2 design decision that Self is always concrete — here, "concrete relative to the generic context" means it tracks the type parameter rather than collapsing to Unknown.

3. **Multi-bound via `+` syntax.** The parser accepts `<T: GeneA + GeneB>` with plus-delimited gene names, matching the conventions of Rust and similar languages. Each bound is checked independently — all must be satisfied, and the body can call methods from any of the bound genes.

4. **Instantiation-site checking completes the static contract.** The bound check at the call site (not the definition site) means generic function bodies are checked against the bound's contract, and callers are checked against the phen registry. This two-sided checking is the standard approach for bounded generics and means the trait system is now a real compile-time contract, not just a runtime dispatch mechanism.
