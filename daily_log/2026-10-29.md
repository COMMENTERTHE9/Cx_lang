## Decisions and direction

**String identity is arena-based, not content-based, inside Results.** This is the key architectural decision in today's commit. Plain `str` equality still compares bytes (content equality). But equality of `Result<str>` values compares by arena identity — each evaluation or named binding gets its own arena slot. This matches the interpreter's `Value` equality semantics, where embedded strings compare by identity. The expected-fail tests explicitly document where this model has known gaps: factory functions that call the same literal produce distinct arena identities, and parameter binding allocates a new arena slice.

**Aggregate Result payloads are snapshot-isolated.** Unwrapping a `Result<[2:t64]>` with `?` creates a local snapshot that is independent of both the stored Result and other unwrapped copies. Mutating the unwrapped copy does not affect the original. This is a correctness property the test `t_result_aggregate_snapshot` pins.

**The packed i128 Result ABI is unchanged.** The commit works within the existing representation rather than redesigning it. Aggregate Ok payloads get aligned, execution-owned snapshots pointed to from the packed word.
