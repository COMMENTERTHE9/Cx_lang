## Landed today

**1. CI stale-base check fix** (`f691ef0`, merged via PR #388 → main) — CONFIRMED

The `stale-base` job in `.github/workflows/ci.yml` was broken in a way that silently passed: it fetched `origin/submain` and measured `HEAD..origin/submain` on every PR, including the 93 open PRs that target main. Because `actions/checkout` gives a `pull_request` run the merge commit (which already contains the base), the count was never branch staleness — it was how far submain led main at run time, a property of the repo rather than the PR.

Fix: the check now reads `github.base_ref` and checks out the PR head commit (`github.event.pull_request.head.sha`) so the base is genuinely absent from HEAD. Without both changes the count would read 0 for every mergeable PR and pass vacuously. The threshold (20 commits) is unchanged.

Changed file: `.github/workflows/ci.yml` (+13/−7).
