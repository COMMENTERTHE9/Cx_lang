**CONFIRMED — `c4527a6` fix(ir): guard INT_MIN/-1 division overflow (Gate-1a)**
First commit of the JIT memory-safety gate series. `INT_MIN / -1` (e.g. `-128 / -1` at t8) trapped in hardware via raw Cranelift `sdiv`. Fix: `emit_guarded_idiv` in `lower.rs` emits a multi-block branch around the faulting divide — checks `dividend == MIN` then `divisor == -1`, producing `MIN` directly without dividing when both hold. The per-width MIN comes from the D1.1 int-facts table. Mod is untouched (srem already handles INT_MIN%-1 correctly). Parity 171→175/100/0: the existing `t_intmin_div_neg1` marker removed (SKIP→PASS), +3 new width fixtures (t16/t32/t64) all convergent. A/B perf: within noise floor (166ms vs 174ms, bands overlap).

**CONFIRMED — `4714cbb` fix(backend): route JIT Trap through cx_trap host-exit (Gate-1b0)**
The Gate-1 audit discovered that `IrTerminator::Trap` was silently broken — the JIT invoked `main` via raw transmute+call with no exception handler, so Cranelift's `trap` (`ud2`) caused STATUS_STACK_OVERFLOW instead of the documented clean exit. Every failing assert/assert_eq and non-exhaustive `when` would have crashed the JIT this way, invisible only because no assert fixture exercised the failure path. Fix: `cx_trap()` — a new `extern "C"` host function imported via the same mechanism as `cx_printn` — prints to stderr and calls `process::exit(126)`. Trap lowering now emits `call cx_trap` + unreachable trap terminator. Exit code 126 is documented JIT_RUNTIME_FAILURE, distinct from 127 (SKIP). New fixture `t_assert_fail` — the first test of the failing-assert path. Parity 175→176/100/0.

**CONFIRMED — `ba2efad` fix(ir): guard division/modulo by zero via clean trap (Gate-1b)**
The final Gate-1 commit, closing the div/mod crash class. Raw `sdiv`/`srem` with divisor 0 trapped in hardware (SIGILL). The `emit_guarded_idiv` helper (from Gate-1a) is extended into the single source for "guard a division": an outer zero-check gate (`is_zero = Eq(divisor, 0)` → Branch to Trap) wraps the existing INT_MIN/-1 inner guard (Div only) and the actual sdiv/srem. The zero-check is the outer gate — a zero divisor traps before any overflow logic. `cx_trap` (Gate-1b0) handles the clean exit. +4 new width fixtures (div/mod-zero at t8 and t64). Parity 176→182/98/0 (178 PASS + 4 new width fixtures). Final submain counts: matrix 280/0, parity 182/98/0, cargo test 243/0, `--features jit` 418/0, clippy 111/0.

## Decisions and direction

**Gate-1 audit methodology:** The commits follow a deliberate layering strategy — the Trap host-exit primitive (Gate-1b0) was built before the division guards that depend on it, and the INT_MIN/-1 guard (Gate-1a) was built independently of the broken Trap path so it could be verified in isolation. Each commit includes its own acceptance test, regression verification, and A/B performance measurement. This is the most disciplined commit series in the project's history.

**Division guard architecture:** `emit_guarded_idiv` is now the single source for "guard a division" — parameterized by op (Div/Rem), it handles both crash classes (zero and overflow) in one CFG structure. The design avoids `select` (which would still execute the faulting instruction) in favor of branch-around. Float division and non-division ops are excluded at the call site (`ty.int_width().is_some()` gate), so their IR is unchanged.

**cx_trap as reusable primitive:** The host-exit mechanism is documented as the foundation for Gate-2 (array bounds checking) and future runtime trap paths. Exit code 126 vs 127 distinction ensures the parity harness never misclassifies a runtime trap as a codegen SKIP.
