## Landed today

**Generic struct lowering** (`5dcd548`) — CONFIRMED. The largest single commit of the submain era: 322 insertions across 14 files spanning `semantic.rs`, `semantic_types.rs`, `lower.rs`, `eval.rs`, and 10 new test fixtures with expected outputs.

What it did, concretely:

- `SemanticExprKind::StructInstance` gained `type_args: Vec<SemanticType>`, retained in declared-parameter order. Both the explicit form (`Pair<t8> { .. }`) and the inferred form (`Pair { a: 1, b: 2.5 }`) populate it — analysis already computed the substitution and was throwing it away.
- `mangle_struct_instance` builds a layout-table key (`Pair$t8`) at the lowering boundary only, following the `mangle_method` / `PhenDef` precedent. The semantic layer never sees the mangled name.
- `build_generic_struct_templates` records the declared shape of each generic struct so a concrete layout can be built on demand at the construct site. A template has no layout (correct), but previously nothing remembered it existed.
- `struct_instance_keys` maps each binding to the layout its storage actually has. This solves the binding-type-erasure problem: `p: Pair = Pair<t8>{..}` and `q: Pair = Pair<t64>{..}` are both typed `Struct("Pair")`, so the access site cannot tell them apart from the type alone. Without this map, both would share one layout and silently corrupt.
- Two explicit erasure consequences: `resolve_field_ptr`'s IR-type cross-check is skipped for instantiations only (the placeholder type would fail it), and print's f64 branch now also routes on the lowered type.
- Five canary/control fixtures: two-instantiation width test (1000000 doesn't fit t8), kind test (f64 vs t32), offset test (t8 fields at 0,1 vs t64 at 0,8), mixed-with-plain test, and unused-template test.

## Decisions and direction

The generic-struct work established two design precedents worth noting:

1. **Mangling at the boundary.** Type arguments stay structured (`SemanticType`) in the semantic layer and only become mangled keys at the lowering table lookup — the same pattern `PhenDef` already uses for method dispatch. This means the semantic tree the interpreter consumes is untouched.

2. **Erasure acknowledgment over erasure repair.** Rather than propagating instantiation types through the binding system (which would touch every `Struct("name")` path), the fix adds a side table (`struct_instance_keys`) that records the information where it's known and falls back to a clean SKIP where it's not. This is explicitly documented as a coverage limit, not a silent gap.

The docs commit filed three prerequisites for generic-function lowering (§19) and explicitly called out that the risk is termination, not scale. The recursive-generic stack overflow (§20) is a crash with no diagnostic whose exit code collides with the SKIP sentinel — both of these need resolution before generic functions can be attempted.
