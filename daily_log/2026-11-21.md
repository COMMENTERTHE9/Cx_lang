## Landed today

### Owner's six decisions implemented (D1–D6) on `backend/value-alias-semantics` — CONFIRMED

The document `docs/backend/cx_decisions_2026_11_20.md` codifies six decisions the owner made in response to the report on PRs #499–#507. Each decision became a testable rule with implementation commits:

**D1 — Non-aggregate receivers are values** (`7098921`, `38fc992`, `899d969`). A receiver whose declared type is a number, bool, char, string, enum, handle, or Result is now treated as a plain value: the method gets a copy, nothing writes back to the caller's variable. The temporary `reject_value_receiver_write` analysis error is removed. Struct and array receivers remain passed by reference as before. Six new test fixtures cover the positive and negative cases.

**D2 — Type parameters are types of their own** (`a7cefe7`, `b32e03c`, `b4129f7`, `e8bb2ac`, `2182771`, `05d8796`, `1512e25`). The largest chunk of work. A new `src/frontend/generic_scope.rs` module (1,007 lines) tracks what each type parameter `T` means inside a generic body and records `Obligation`s — things the body does that are correct only for some concrete types. A new `check_instantiations` pass walks every call site (direct and transitive through other generics, up to a per-function cap) and verifies each obligation against the actual types. This closes known-issues §74 (generic mismatch between interpreter and compiled code) and replaces it with §81 (the new generic rule). Over 40 new test fixtures were added, covering array literals with mixed types, branch values, struct fields, nested generics, forward-declared functions, and the rejection cases.

**D3 — Constant Ok payloads take the declared type** (`f86ce93`, `3f8fd30`). A `Result<t8>` declared variable can receive `Ok(5)` without error — the constant 5 fits in a `t8`. Division and remainder in constant expressions are also permitted. Five new test fixtures pin the positive and negative cases.

**D4 — When-value exhaustiveness on bools** (`a1aeb13`). The `true / false / unknown` arm set makes a `when` value exhaustive only when the scrutinee is a `bool`. Previously, three-state arms on a number were silently accepted. One new rejection fixture.

**D5 — Method calls on type parameters** (`6ef02cf`). A method call on a value of type `T` is now resolved per-call-site: the analysis checks whether the method exists on whatever concrete type the caller provides for `T`. This feeds the receiver-access analysis (D6).

**D6 — Receiver variable reachability** (`899d969`, `3cba86e`, `0a2a283`). A new `src/frontend/receiver_access.rs` module implements the rule that a method must not be able to reach its receiver's caller-side variable by name. If the method's body, or any function it calls, could read or write the variable that the caller gave as the receiver, the program is rejected. This prevents aliasing between the method's receiver reference and a by-name access to the same variable. The check is conservative: if it cannot determine reachability (e.g., through an undetermined type parameter), it refuses. Six new test fixtures.

## Decisions and direction

The day was dominated by implementing the owner's six decisions of 2026-11-20. These are the most consequential language-level decisions since the value-semantics amendment itself:

1. **Value receivers for non-aggregates (D1)** establishes that numbers, bools, strings, enums, handles, and Results are passed by value to methods. Only structs and arrays retain pass-by-reference receiver semantics. This simplifies the mental model and closes the aliasing risk for scalar types.

2. **Generic type-parameter safety (D2)** is the largest architectural addition. The new `generic_scope.rs` module introduces an obligation-based checking system that catches type mismatches inside generic bodies at analysis time, before they reach the backend. This was one of the longest-standing gaps between the interpreter and compiled code.

3. **Receiver variable reachability (D6)** prevents a subtle aliasing hazard: a method receiving a struct by reference could also access the same variable by name, creating two paths to the same memory. The new analysis rejects programs where this is possible.

The branch stack is now four branches deep: `generic-local-interpreter-fix` → `ci-windows-gates` → `result-type-analysis` → `value-alias-semantics`, totaling 190 commits ahead of main on the top branch. Integration will require the owner's review and decisions on the remaining items.
