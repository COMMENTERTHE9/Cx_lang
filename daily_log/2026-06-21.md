## Decisions and direction

The D2.x-A1/A2 commits represent a concrete design decision about how the IR handles Cx's three-valued boolean system. Key architectural choices evidenced in the code:

- **TBool lives on the I8 wire, not a separate representation.** The unknown state (2) coexists with false (0) and true (1) on the same I8 wire encoding, using Cast between I8 and TBool to satisfy the IR validator's type constraints. This mirrors the interpreter's approach in `runtime/ops.rs`.

- **Kleene logic is implemented as CFG, not as a Select instruction.** Because the IR has no `Select` (conditional move) instruction, each three-valued operation generates a small compare/branch/merge block graph. The commit notes this explicitly as a design constraint, not an oversight.

- **The `==`/`!=` TBool refusal is deliberate and deferred.** The IR's Compare instruction yields a definite Bool; it cannot produce a three-state result. Comparing two TBool values would silently miscompile. This is explicitly marked as the Path-B seam — numeric unknown lowering is a future workstream, not a bug.

- **Structural type probing (`expr_lowers_to_tbool`) avoids committing to the wrong CFG.** The definite-Bool short-circuit path for `&&`/`||` lowers rhs eagerly into its own block. If that block receives a TBool, it would fail. The structural probe detects TBool operands before lowering, routing to Kleene instead. This is a pragmatic workaround for the lack of a type-directed lowering pass.
