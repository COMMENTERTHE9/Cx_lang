## Landed today

- **CONFIRMED** — `d53784b` on `submain`: "feat(semantic): gene/phen declarations + Pass-0 coherence registry (0.3.4 slice 1 of 6)". This is a substantial commit (381 insertions across 24 files) that lays the foundation for the gene/phen trait system. Specifically:

  - **Lexer**: `gene` and `phen` keywords added as reserved tokens.
  - **Parser**: Full grammar for `gene` blocks (signature-only method declarations — bodies are intentionally a parse error) and `phen` blocks (full method implementations with a typed receiver binding). Gene methods use arrow-style return types; phen methods reuse the existing `fnc` definition grammar from impl blocks.
  - **AST**: New `Stmt::GeneDef` and `Stmt::PhenDef` variants, plus a `PhenMethod` type alias matching the impl-block method shape.
  - **Semantic analysis — Pass 0**: A new `collect_gene_phen_registry()` function that runs before any per-file analysis. It scans the entire resolved program (all files in topo order) to build a gene name set and a phen registry keyed on `(gene_name, receiver_type)`. Catches undeclared-gene references and duplicate phen registrations with two-location diagnostics (file path + line number of the first registration). This is deliberately NOT a field on `Analyzer` — it's a whole-graph pass, matching the design doc's coherence decision (item 5).
  - **Semantic analysis — per-file**: Gene and phen declarations get header-only mirrors into the `SemanticStmt` tree. Method bodies in phens are deliberately NOT analyzed yet — no binding for the receiver, no body walking, no Self substitution. That's slices 2–6.
  - **SemanticType**: `Hash` derive added to `SemanticType` so it can be used as a HashMap key in the coherence registry.
  - **IR lowering + runtime**: Both arms return `Ok(Some(current))` / `Ok(())` respectively — gene and phen are inert at execution. The infrastructure exists so the rest of the pipeline doesn't crash on the new variants.
  - **Diagnostics**: Debug printing for the new AST nodes.

## Decisions and direction

The commit confirms several design decisions from `docs/post_0_1/gene_phen_design.md` are now being implemented as specified:

1. **Pass ordering**: Pass 0 (whole-graph gene/phen collection) runs before any per-file semantic analysis, exactly as the design doc's "Semantic-Pass Ordering" section specifies. This is the first multi-pass structure in the Cx semantic pipeline.
2. **Coherence is first-wins with collision-at-insert**: The `phen_registry` HashMap catches duplicates at insertion time with a two-location diagnostic. Order-independent because it's a single flat scan, not an incremental per-file walk.
3. **Gene is signature-only, no bodies**: Bodies inside a gene are a parse error by design — the grammar doesn't include a body block, so `{` falls through to a clean parse error. No special-case detection needed.
4. **Phen reuses impl-block method syntax**: The parser's `func_def` combinator is reused directly for phen method bodies, confirming the design's intent that phens are "full implementations exactly like an impl block's."
5. **Sliced delivery**: The commit explicitly scopes itself as "slice 1 of 6" — declarations and coherence only. Method-call resolution, Self substitution, conformance checking, and execution are deferred to later slices.
