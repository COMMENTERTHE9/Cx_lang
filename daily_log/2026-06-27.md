## Decisions and direction

The packed-i128 representation for Result is a carefully considered design choice. The commit messages explicitly explain why arithmetic packing was rejected: `Cast i64->i128` (sextend) would smear a negative payload's sign bits into the tag half. The memory round-trip — store payload and tag into separate 8-byte halves, then load as i128 — is heavier but keeps the fields byte-isolated. The `t_result_ok_negative` canary fixture pins this invariant.

The word-payload fence is another deliberate boundary: Result<T> only works when T fits in a single i64 word (scalars or static Ptr). `Result<Result<T>>` is refused at the `widen_payload_to_i64` entry point with a clear error citing R7-deferred. This is honest about the rep's limits rather than silently producing wrong code.

The `?` operator's Err early-return path reuses the plain Return terminator with zero overlap with the unknown-`?`/TBool machinery — the commit notes these are independent arcs. This matters because TBool's unknown propagation also uses `?` syntax but with different semantics.

The Cranelift `enable_llvm_abi_extensions` ISA flag is load-bearing while Result uses i128 — the commit explicitly notes it is not removable.
