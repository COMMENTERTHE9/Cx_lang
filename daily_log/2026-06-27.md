## Landed today

- **CONFIRMED** — `71c4160` (submain): **D2.4a — Result representation + construct + print.** Result<T> is a packed i128: tag in the high 64 bits (Ok=0, Err=1), payload word in the low 64. Construction uses a memory round-trip (Alloca → Store payload@0 → Store tag@8 → Load i128) rather than arithmetic packing — the raw-byte layout is deliberate, because sign-extending a negative Ok payload (e.g. Ok(-5)) would corrupt the tag bits. The `enable_llvm_abi_extensions` Cranelift ISA flag was added to `host_boundary.rs` because the x64 ABI rejects i128 args/returns without it. `print(Result)` is a tag-branch inline print sequence reusing the D2.3d host functions, matching the interpreter's `Ok(15)` / `Err(cannot be zero)` output byte-for-byte. New canary fixture `t_result_ok_negative.cx` pins the negative-payload invariant. Files: `src/ir/lower.rs` (+252 lines), `src/backend/cranelift/host_boundary.rs` (+8 lines), 2 new test fixtures.

- **CONFIRMED** — `a32a242` (submain): **D2.4b — The `?` (Try) operator.** `expr?` on a packed-i128 Result unpacks via `result_unpack`, branches on the tag. Ok: the payload word is narrowed back to T (ireduce, reversing the construct's widen) and execution continues. Err: the whole original Result i128 is early-returned unchanged from the enclosing function via the plain Return terminator — the propagated Err arrives at the caller byte-identical. The semantic analyser already guarantees `?` only appears inside a Result-returning function and only on a Result<T> operand (t85/t86 rejects), so the lowering doesn't need a return-type lookup. A word-payload fence refuses nested-Result `?` (R7-deferred). Test fixtures t83 (unwrap + propagate) and t84 (2-level chain) convert. File: `src/ir/lower.rs` (+78 lines).

- **CONFIRMED** — Both commits are branch-local to submain and have not been merged to main. Submain is now 24 commits ahead of main. No merge activity today.

## Decisions and direction

The packed-i128 representation for Result is a carefully considered design choice, not just an implementation detail. The commit messages explain why arithmetic packing was rejected: `Cast i64→i128` (sextend) would smear a negative payload's sign bits into the tag half, making Ok(-5) look like Err. The memory round-trip — store the payload and tag into separate 8-byte halves, then load the whole 16-byte slot as i128 — is mechanically heavier but keeps the two fields byte-isolated. This is a load-bearing design decision that the `t_result_ok_negative` canary fixture explicitly pins.

The word-payload fence is another deliberate boundary. Result<T> only works when T fits in a single i64 word (scalars or static Ptr). Result<Result<T>> is explicitly refused at the `widen_payload_to_i64` entry point with a clear error mentioning R7-deferred. This is honest about the rep's limits rather than silently producing wrong code.

The `?` operator's EarlyReturn path reuses the plain Return terminator with zero overlap with the unknown-`?`/TBool machinery — the commit explicitly notes these are independent arcs. This matters because TBool's unknown propagation is a separate language feature that also uses `?` syntax but with different semantics.
