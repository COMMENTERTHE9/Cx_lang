## Landed today

**CONFIRMED — `f654416` (D2.5a): Handle.new construct lowered** (2026-07-04T11:17:51, submain)

The Handle representation is a packed i64: `slot | (gen << 32)`, where both slot and generation are unsigned u32s. The shift uses the u64 reinterpretation to avoid sign-extension corruption. `lower_type(SemanticType::Handle(_))` now returns `IrType::I64`.

The runtime state lives in a `HandleRegistry<i64>` behind a process-lifetime `OnceLock<Mutex<...>>` static in `host_boundary.rs`. This is the only workable pattern because `jit_builder.symbol()` registers by raw function pointer and can't accept a state-capturing closure. Safe because `run_jit_subprocess` spawns a fresh OS process per fixture.

A new `widen_handle_payload_to_i64` helper converts the inner expression's lowered type to i64, scoped to `{I8, I16, I32, I64, Bool}`. Two types are deliberately excluded: Ptr (would recreate the Handle<str> landmine — a later .val read couldn't distinguish a raw scalar from a string descriptor pointer) and F64 (Cast(F64→I64) lowers to `fcvt_to_sint_sat`, a numeric conversion that silently truncates 3.14 to 3).

One stale unit test was fixed: `rejects_handle_type` renamed to `rejects_handle_type_mismatch` — it asserted Handles are wholesale-unsupported, which is no longer true.

New fixture: `t_handle_construct_cross_fn` (PROVISIONAL — superseded once t16 passes). Matrix: 294/0, parity: 234/60/0 (+1 PASS).

Files: `src/ir/lower.rs` (+96/-6), `src/backend/cranelift/host_boundary.rs` (+56).

**CONFIRMED — `37b71f2` (D2.5b): Handle.val (read) lowered** (2026-07-04T12:31:37, submain)

This was the harder half. The investigation falsified the "uniform-i64" hypothesis: `ensure_type_match` is strict equality everywhere downstream, and HandleVal's semantic claim (I128) has no T-blind `lower_type` collapse protecting it. So `.val` produces a genuine `IrType::I128`, not a raw i64.

The read path: call `cx_handle_val(handle: i64, out_valid: *mut i8) -> i64`, check the out-parameter, branch to Trap on invalid, then widen the payload from i64 to I128 via Cast (sign-extend). The out-parameter pattern (not a sentinel) was necessary because the packed slot+gen bit-space is fully dense — no reserved "invalid" pattern exists that wouldn't collide with a legitimate handle. The out-parameter mechanics reuse Result's proven Alloca/Store/Load pattern, scaled to a 1-byte scratch slot.

The invalid path terminates with `IrTerminator::Trap` → `cx_trap`, the same mechanism assert and when-exhaustiveness already use. The Trap path is structurally correct but its empirical proof is deferred to D2.5c — there's no way to construct an invalid Handle via Cx source today (HandleDrop doesn't exist yet, and uninitialized reads reject at semantic analysis).

Three new canary fixtures:
- `t_handle_val_positive` — baseline round-trip
- `t_handle_val_negative` — negative t32 payload via a function parameter (not a bare literal), proving sign-extension composes across both widening stages
- `t_handle_val_bool` — true/false discrimination via cross-comparison of independently-constructed Handles, sidestepping an interpreter tag-mismatch in assert_eq

Matrix: 297/0, parity: 237/60/0 (+3 PASS).

Files: `src/ir/lower.rs` (+88/-1), `src/backend/cranelift/host_boundary.rs` (+61).

## Decisions and direction

**Handle representation is settled.** The packed-i64 choice (slot low, gen high, unsigned shift) is now load-bearing across two commits. The out-parameter pattern for validity checking (not a sentinel, not a Rust-style Result) was chosen because the bit-space is fully dense.

**Payload type restrictions are intentional, not temporary.** Ptr and F64 exclusion from Handle payloads is a design decision with safety reasoning, not a TODO. Ptr would create an opaque-pointer-through-Handle escape that can't be validated on read. F64 would silently truncate via `fcvt_to_sint_sat`.

**Empirical Trap proof is explicitly deferred.** The D2.5b commit documents why the stale-handle Trap path can't be empirically tested yet (no HandleDrop in the language) and where it will be tested (D2.5c, where generational reuse naturally produces stale handles).
