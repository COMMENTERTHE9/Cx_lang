## Actual compiler and language state

Parsing produces an AST; import resolution builds the module graph; analysis
resolves names/types and produces a semantic program. The interpreter executes
that program directly. The native path specializes generic functions, builds
signatures/layouts, lowers to Cx IR, and emits Cranelift JIT code. `validate`
lowers and checks IR. The CLI's normal JIT dispatch does not invoke the standalone
IR validator; its checks and Cranelift verification are distinct gates.

Working coverage includes signed declared-width arithmetic, floats, tri-state
bool, strings, structs/methods, genes/phens and operators, enums, Results,
control flow/matching, generic functions/structs, fixed and contiguous nested
arrays, aggregate returns and value copying, and scalar generational handles.
Support is conditional on representation: generic type information can still
be erased, and some programs are refused by one backend. For example,
`Cell<Color> { v: Color::Green }` currently fails analysis with the misleading
message “expects Color but got Color” on both backends. This is a remaining
semantic gap, not fixed by printing recovery or verified as working generics.

The interpreter remains the reference for defined behavior, but is not assumed
infallible. PR #462 concerns an interpreter generic conversion bug as well as
native agreement. Monomorphization has an explicit 64-instantiation limit;
both execution paths have call-depth guards. Neither limit proves arbitrary
program termination.

Arrays and structs use the established value-copy model, with a declared
receiver exception. Native aggregate returns use caller-owned slots. `.copy`
passed-by-address write-back landed in August; `.copy.free` is accepted with a
deprecation warning. `copy_into` remains blocked by Container representation.
The interpreter stores string bytes in a runtime-owned arena; JIT static string
bytes/descriptors use leaked process-lifetime storage. Repeated lowering in a long-running host therefore retains those allocations;
runtime allocator/lifetime tooling remains incomplete.
Scalar handles check generations, but richer payloads and ownership operations
are not complete. No memory model or ABI was redesigned in this task.

The most limiting native gaps are module-level state used by functions, nested
functions, container copy, and practical string/I/O coverage. Further refusals
include `while-in`, chars, t128 printing and large/nested Result payloads.
Functions accessing top-level bindings are honestly refused rather than given
incorrect local storage. Both Cranelift AOT and LLVM AOT are explicit stubs;
there is no native executable/linking deliverable or established C interop path.
Static strings currently embed process-specific addresses in IR, so AOT also
needs relocatable static data rather than simply enabling object emission.

Diagnostics have source excerpts, phase tracing, IR printing, rejection-shape
tests and recursion errors. Some AST/runtime errors still carry position zero
and point at line 1. Interpolation validation/scoping and generic checking
remain incomplete. Unknown backend names silently choose the interpreter.
CI covers Linux build/matrix and JIT tests plus stale-base/branch guards; it
does not run a Windows/Linux conformance matrix. This session verified Windows,
not Linux, stable Rust, AOT, FFI, exhaustive memory safety or release readiness.

The README mixed release-era counts with current claims, listed already-landed
expression receivers and `.copy` as missing, and drew the interpreter after IR.
Those claims are corrected in this change. The living roadmap was dated August;
it now identifies the immediate milestone and preserves the historical version
sequence. The frontend/backend 0.1 phase roadmaps are explicitly historical,
and should not be read as live delivery status.

## Recommended next milestone and completion criteria

**Whole programs compile and agree** should precede AOT and wider feature work.
Wrong output and functions unable to use module state block useful tools more
directly than missing optimized object emission. Keep the existing language and
ABI contracts; bring genuinely unspecified initialization/ownership behavior to
the user with a concrete recommendation before implementing it.

1. Finish and integrate this printing packet after its gates pass.
2. Independently verify PR #462's generic conversion behavior and reconcile the
   nested-function draft as a separate change. Do not merge stacked drafts as a
   single compiler rewrite. Each needs positive, negative and parity regressions.
3. Add module-binding identity/storage and validation to IR, then lower function
   reads of initialized scalar constants. Add mutable scalar state separately,
   retaining textual initialization order, immutability checks and behavior on
   access before initialization. Extend to aggregates through existing copy and
   return-slot machinery, with alias and module-collision tests.
4. Add a small multifile tooling workload with module constants/state, imports,
   functions, arrays, Results and useful output. Pin outputs, mutations, exit
   codes and failure shapes on both backends. Run the gates on Windows and Linux.

Close this milestone when that workload and its regressions agree without
compiler crashes, supported programs have not become SKIPs, and every remaining
refusal has an explicit reason. Then complete container copying and remaining
supported-surface lowering, improve strings/I/O and allocator lifetime tools,
and grow a small standard library around actual tooling needs.

The established broader sequence remains: library/runtime maturity, Cranelift
object emission then linking, target/ABI conformance and C boundary design,
followed by LLVM optimization and bootstrapping. Measure performance on
representative workloads before optimizing. Release preparation requires
version/package consistency, reproducible documented examples, diagnostics,
platform gates and human approval for main/release actions. Graphics and later
engine systems remain downstream goals, not this milestone's scope.
