The interpreter and the JIT have been quietly disagreeing about what values programs produce. Not crashing, not erroring, just returning different numbers depending on which backend ran the code. That class of bug got a lot smaller today.

Nine PRs merged to submain in a single evening session, carrying 18 work commits and roughly 80 new test fixtures. The work breaks into three threads: making literals and arrays type-safe across both backends, fixing module and scope semantics, and closing JIT correctness holes in compound assignment, branch types, and enum limits.

## Literal type-checking and declared-type propagation

The core bug: a `t8` field initialized from a `t32` variable holding 300 kept 300 on the interpreter but stored 44 (narrowed) on the JIT. The two backends had never agreed on what a literal in a typed position meant.

PR #454 fixed the root cause. `insert_cast_if_needed` now converts each struct-literal field and array-literal element to the declared type, so both backends see the same narrowed value. PR #457 extended this to every typed position: assignments, method arguments, if/when branches, nested arrays. It also corrected a subtlety where "widening" was letting a declared type leak into neighboring expressions. That's been withdrawn. Each typed position gets its own cast, not scope-level type inheritance.

## Arrays have one element type

This is a language-level decision that landed in code. Before today, `types_compatible` accepted any two numeric arrays of the same length as compatible. A `[3: t8]` would go into a `[3: t64]` slot with no conversion. The interpreter kept each value at its original width; the compiled code read at the declared width and produced garbage (67305985 instead of the expected value).

Now, different element types are a type mismatch at analysis time. Untyped array literals take their type from the first non-literal element. Follow-up commits closed holes around generic `T` elements, forward-call `.copy` types, nested generic literals, and a compile-time regression where nested generic calls at depth 20 dropped from 12.4 seconds to 0.25 seconds.

## Module naming by identity

Multi-module programs had four separate defects. A library couldn't call its own functions because they were renamed to `alias$name` but internal calls used the bare name. Two aliases of one module only resolved the first. Same-alias imports of different modules created duplicate symbols. And every file could see every alias regardless of its own imports.

The fix keys modules by `alias@id` and scopes import visibility per-file. This makes multi-module programs sound for the first time.

## Compound assignment operand checking

`x op= y` was checking neither operand. Compound assignment on an enum, bool, unbounded generic `T`, or struct produced silent miscompilation. The interpreter kept full-width sums while the JIT wrapped, or the JIT did integer addition on a struct's address and segfaulted.

The rule now is clean: if `+` refuses the operands, `+=` refuses them too. No separate, weaker rule for compound assignment.

## JIT branch type matching and enum limits

Two more JIT correctness fixes landed. Programs with definitions but no top-level statements now run as empty programs instead of failing to compile. Enums with more than 256 variants are refused instead of wrapping the tag into 8 bits.

And branch-type checking was added to `if`/`when` value expressions. Previously, an enum and a `t8` sharing the I8 IR type, or two different structs sharing a pointer type, would compile one value as the other without any diagnostic. The lowerer now checks semantic types, not just IR types.

## Impl method scoping

A small but important scope fix: an impl method's name now belongs to its type, not the global scope. Two structs each defining a method called `add` was previously a name collision. It no longer is.

## What's still in progress

The `backend/generic-value-conversion` branch has two commits not yet merged. Generic bodies are checked once with `T` unknown, so a `T` value going into a `t8` slot had no cast. This is the natural next PR.

Submain is now 44 non-merge commits ahead of main, carrying today's work plus earlier features (top-level state refusal, imported-call checking, function-name scoping, float division safety). Main still holds at 414 tests; submain has 564. The gap keeps growing.

None of today's work checks off a roadmap-listed lowering blocker. Array returns, expression receivers, `.copy_into`, nested functions, `while-in`, `t128` printing, `char`, and non-identifier string interpolation all remain. What today's work does is make the existing lowered subset sound: when the compiler accepts a program, both backends produce the same answer.

## What's next

The generic value conversion branch is ready to merge. Beyond that, `known_issues.md` still lists positions where the backends disagree, so the type-safety sweep may have more to go. The submain-to-main merge is overdue at 44 commits, and the lowering blockers (`copy_into`, nested functions, `while-in`) are waiting for the correctness sweep to wind down.

The overarching theme from this session is straightforward: the two backends must agree, and when they can't, the program is refused at compile time rather than silently producing different results.
