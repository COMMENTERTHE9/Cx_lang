## The design spec is implementation-ready

The gene/phen design doc on submain (`docs/post_0_1/gene_phen_design.md`) is not a sketch. It specifies pass ordering, canonical key format, collision detection, diagnostic text, and defines eight required test fixtures. This is the foundation for the 0.3.4 milestone.

The roadmap reflects this accurately: 0.3.1 shipped and tagged on main, 0.3.2 (pattern matching) not started, 0.3.3 (gene/phen design) complete on submain but not tagged or merged, and 0.3.4 (gene/phen implementation) not started.

## What happens when work resumes

The path forward is well-defined:

1. Merge submain to main. The 13 commits include the design spec, parser fixes, and CI cleanup. The design phase being complete removes any technical reason to hold it back.
2. Start 0.3.4 gene/phen implementation. The spec lays out what to build and in what order.
3. Known issue #3 (explicit return plus trailing expression) is still open and lives in the same code region as the #2 fix already on submain.

Quiet stretches happen. The useful thing to note here is that when this one ends, the project isn't starting from a blank page. The design work is done, the spec is concrete, and the merge is mechanical. The gap between "no commits" and "implementation underway" is smaller than the commit graph makes it look.
