If you write `b: bool = unknown` in Cx today, the compiler tells you exactly what you meant: "`unknown` is a pattern keyword, not a value -- use `?` for the unknown literal." Two weeks ago it would have blown up at the `:` token with a 20-token "expected" dump that never mentioned `?`. That is the kind of diagnostic improvement that saves a new user ten minutes of confusion, and it is what landed today.

## The fix

Tracker item #039 targeted `unknown` used in value position. In Cx, `unknown` is a pattern keyword (you use it in `when` blocks), while `?` is the literal for an unknown value. The distinction matters, but if you are new to the language or coming from something where `unknown` works in both positions, the old error gave you nothing to work with.

The fix adds a `KeywordUnknown` alternative to the primary expression parser. When the parser sees `unknown` where a value expression is expected, it emits a targeted error at that exact span instead of falling through to the statement parser and cascading. The recovery path produces `AstValue::Unknown` so the diagnostic points at the offending token rather than somewhere downstream. The error still correctly fails the parse, so nothing unsound leaks through.

Two new test fixtures cover the behavior: `t_unknown_as_value.cx` and `t_unknown_as_value.cx.expected_fail`. The change touches 18 lines in `src/frontend/parser.rs`. Commit gates on submain report 243 unit tests passing and a 208/0 matrix, so the fix does not disturb the existing `?` literal path or `unknown`-in-when-pattern handling (those live in separate parser branches).

## Pattern: name the right syntax in the error

This commit follows the same design pattern established over the prior two days of the tracker sprint. When a programmer reaches for syntax that is intuitively plausible but wrong in Cx, the compiler names the correct syntax directly. Tracker #038 did this for string interpolation errors. Tracker #013 did it for `let ... = expr` used as a directive. Now #039 does it for `unknown` vs `?`.

The philosophy is straightforward: a generic parse failure that lists twenty possible tokens teaches the programmer nothing. A message that says "you wrote X, you want Y" resolves the issue in one read. These are small commits individually, but the cumulative effect on the first-run experience is significant.
