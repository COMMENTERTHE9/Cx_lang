## Audit findings: closed out

Finding 3.3 was the ordering-comparison gap. The semantic layer's handling of `<`, `>`, `<=`, `>=` had a fallthrough path that accepted any operand pair that wasn't numeric, including `Bool` and `Enum`. Those operand pairs would pass semantic analysis and then crash at runtime. The fix in `semantic.rs` restructures the else-branch so ordering comparisons are accepted only when both operands are numeric. Everything else gets a compile-time rejection now, which is the correct behavior.

Finding 3.4 was a CI maintenance risk. The CI workflow had a 50-line inline reimplementation of `run_matrix.sh` that was already drifting from the canonical script -- missing output-verification mode, missing expected-fail handling nuances. The fix replaces that entire inline block with a single `bash src/tests/run_matrix.sh` call. Future matrix improvements now apply to both local and CI runs automatically.

With 3.1 (scope leaks) and 3.2 (width-range enforcement) already fixed in earlier sessions, the audit backlog is clear.

## Enum equality: filed and fixed in two hours

This one is worth calling out because it's the third instance of the same bug pattern. During regression testing for finding 3.3, enum `==`/`!=` comparisons turned out to crash the interpreter. The semantic layer correctly allowed the comparison, but `ops.rs` had no `(Value::EnumVariant, Value::EnumVariant)` arm in either `Op::EqEq` or `Op::NotEq`. Both fell through to the `BadOperands` catch-all.

The JIT already handled this correctly through its integer-tag representation. The fix adds explicit arms comparing both `enum_name` and `variant_name` fields. Known issue #9, filed at 15:57, fixed at 17:09.

This is the same pattern as the f64 comparison crash (known issue #1): the type system promises support that the runtime dispatch table doesn't implement. Worth watching for more instances of this as the type system grows.

## Gene/phen design spec committed

The gene/phen trait system design has been living outside the repo until today. This commit brings in the v1.1 spec as `docs/post_0_1/gene_phen_design.md` (135 lines) and updates the roadmap to cross-reference it from the 0.3.3 entry.

For context: gene is the contract side (like a trait or interface) and phen is the expression side (the implementation). The split is the foundational abstraction for operator overloading, bounded generics, and the stdlib. Every post-0.3 feature depends on it. The spec covers gene and phen declarations, bounded generics via `where T: Gene` syntax, static dispatch by default with explicit `dyn` for dynamic dispatch, and the stdlib dependency chain.

The design is marked "locked" at v1.1. That doesn't mean implementation has started, but the target for the 0.3.3 design-pass milestone is now formally specified and tracked.
