The range-check sweep is done. CR#4 landed on submain today, closing the last identified gap in the #028/#037 literal width-check series. `check_semantic_num_fits` now descends into if/when branch tails, and the old `check_literal_fits` function is deleted. Submain stands at 261 tests, 0 failures. Main holds at 230/0, unchanged.

## What CR#4 actually fixes

The bug: out-of-range integer literals inside `if` or `when` expression branches were accepted silently and wrapped at runtime. A concrete example: `x: t8 = if c { 300 } else { 5 }` compiled without complaint and produced 44 at runtime (300 wrapped into 8-bit signed). The compiler had range checks for direct assignments and struct fields, but expression-position branches slipped through because the checker never walked into branch tails.

The fix adds a `check_branch_tail_fits` helper that recurses through nested if/when structures, feeding each tail expression into `check_semantic_num_fits`. That function already handled the actual width arithmetic. The new code just makes sure it sees every literal, regardless of how many levels of branching wrap it.

Nine new verification matrix fixtures pin the behavior across seven reject sites (declarations, struct fields, field assignments, array elements, call arguments, returns) plus a nested-negative case and an in-range pass guard. Gate results: cargo test 243/0, JIT parity 164 PASS / 97 SKIP / 0 PARITY_FAIL, run_matrix 261/0.

## Unifying the width-check path

The more interesting part of CR#4 is architectural. Before this commit, literal width checking existed at two abstraction levels: `check_literal_fits` operated on AST `Expr` nodes, and `check_semantic_num_fits` operated on `SemanticExpr` nodes. Structurally identical logic, duplicated across abstraction layers.

CR#4 deleted `check_literal_fits` entirely. Both remaining call sites (typed declaration and struct-field literal) migrated to the semantic-level check. Every width-check path now routes through a single function. That means future work on this surface only has to happen in one place.

The commit message documents equivalence verification: structurally identical parallel match arms, behavior confirmed by pinning bare, negated, boundary, over-range, and type-mismatch inputs before switching, with no divergence. The old function is gone, not just deprecated.
