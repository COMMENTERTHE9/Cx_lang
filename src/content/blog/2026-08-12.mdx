## Yesterday's site branch update

The only activity in the 24-hour window was automated. A retroactive blog post went up on the site branch covering the August 3 cycle-only call-depth guard optimization. That post documents how `functions_that_can_recurse()` in `host_boundary.rs` uses Tarjan's SCC algorithm to restrict depth guards to recursive call paths only, with measured results showing non-recursive code paying zero overhead. The optimization traded about 130 lines of call-graph analysis code for that zero-overhead property on non-recursive paths. This was already recorded in submain's documentation commits; the blog post is the public-facing summary.
