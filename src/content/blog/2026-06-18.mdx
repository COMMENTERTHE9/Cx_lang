The main branch roadmap had been stale since 2026-05-18, a full month out of date. That gap finally got closed today. The update reflects work that had already landed on submain but was never recorded:

- `when` block lowering is checked off. D1.2a (unified stmt/expr emission) and D2.1 (shared branch-value merge) confirmed it on submain.

None of this is new work. It is bookkeeping that tracks what submain already proved. But bookkeeping matters: a stale roadmap is a roadmap nobody trusts, and a roadmap nobody trusts stops being useful for planning.

## The integration gap

Submain sits 15 commits ahead of main. All 15 are tested (286 matrix fixtures, 0 failures, 199 parity PASS, 87 SKIP, 0 PARITY_FAIL). The merge to main has been predicted in the daily logs for multiple days running and keeps not happening.

This is not a stability concern. The commits are stable. But a 15-commit gap between the development branch and main means main is increasingly unrepresentative of where Cx actually is. Anyone looking at main sees a project that is a month behind its own working state.

## The PR backlog

There are 20 open daily-log PRs (May 28 through June 17), none merged. Each PR independently updates ROADMAP.md, so the branches have divergent roadmap states. The PR-first workflow for daily logs may be creating more friction than it prevents.

This is worth watching. If the backlog keeps growing without merges, the workflow is generating overhead without delivering its intended benefit (incremental integration of log updates). At some point the right move is either to batch-merge or to rethink how daily log changes flow into main.
