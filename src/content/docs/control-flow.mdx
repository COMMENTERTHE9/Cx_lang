## Status

Control flow is stable in the interpreter. `if` / `else` and `for` are JIT-lowered and parity-gated. `while` and `loop` have partial JIT coverage. `when` lowers to the JIT for literal, range, definite-bool, and enum-variant patterns; matching an actual unknown-valued (`?`) TBool does not yet lower.

## If And Else

`if`, `else if`, and `else` work.

<SourceComment source="origin/submain:examples/fizzbuzz.cx" />
```cx
let i;
i = 1
while (i <= 20) {
    if i % 15 == 0 {
        print("FizzBuzz")
    } else if i % 3 == 0 {
        print("Fizz")
    } else if i % 5 == 0 {
        print("Buzz")
    } else {
        print(i)
    }
    i += 1
}
```

## If And When As Expressions

`if` and `when` both produce a value directly — the chosen branch (or arm) is the value, so either can be assigned or returned.

<SourceComment source="origin/submain:src/tests/verification_matrix/t_if_expr_is_large.cx" />
```cx
fnc: bool is_large(n: t64) { if n > 100 { true } else { false } }
print(is_large(50))
print(is_large(200))
```

<SourceComment source="origin/submain:examples/when_match.cx" />
```cx
fnc: t64 tier(n: t64) {
    when n {
        0       => 0,
        1..=9   => 1,
        10..=99 => 2,
        _       => 3,
    }
}

print(tier(0))
print(tier(7))
print(tier(42))
print(tier(500))

level: t64 = 7
size: str = when level {
    0     => "none",
    1..=9 => "small",
    _     => "big",
}
print(size)
```

A consumed `if` (one whose value is used) must have an `else` — both branches produce the value. Used as a plain statement, `if` needs no `else`.

An unknown-valued `if` condition is rejected the same way an unknown value can't choose a `when` arm:

<SourceComment source="origin/submain:src/tests/verification_matrix/t_if_expr_unknown.cx" />
```cx
b: bool = ?
x: t64 = if b { 1 } else { 2 }
print(x)
```

```text
RUNTIME ERROR: `if` condition is unknown; an unknown TBool can't choose a branch —
use `when` to handle true, false, and unknown explicitly
```

## While

`while` works in the interpreter. The JIT has PASS and SKIP fixtures.

<SourceComment source="origin/submain:src/tests/verification_matrix/t132_while_loop_exit.cx" />
```cx
fnc: t64 sum_loop(n: t64) {
    total: t64 = 0
    i: t64 = 0
    while (i < n) {
        total = total + i
        i = i + 1
    }
    return total
}

assert_eq(sum_loop(5), 10)
```

## For

Range `for` loops work and have full category PASS in the current JIT parity table.

<SourceComment source="origin/submain:src/tests/verification_matrix/t149_for_loop_exit.cx" />
```cx
total: t64 = 0
for i in 0..5 {
    total = total + i
}
assert_eq(total, 10)

sum: t64 = 0
for i in 1..=4 {
    sum = sum + i
}
assert_eq(sum, 10)
```

## Loop And Break

`loop` and `break` work in the interpreter. JIT coverage is partial.

<SourceComment source="origin/submain:src/tests/verification_matrix/t106_loop_break_in_func.cx" />
```cx
fnc: t64 find_first_even(start: t64) {
    i: t64 = start
    loop {
        if (i % 2) == 0 {
            break
        }
        i += 1
    }
    return i
}
print(find_first_even(7))
```

## Labeled Break And Continue

A loop can be labeled (`'name: loop { ... }`), and `break` / `continue` can target a label to act on an outer loop instead of the innermost one.

<SourceComment source="origin/submain:src/tests/verification_matrix/t_labeled_break_outer.cx" />
```cx
let out;
out = 0
'outer: loop {
    out = out + 1
    loop {
        break 'outer
    }
    out = out + 100
}
print(out)
```

<SourceComment source="origin/submain:src/tests/verification_matrix/t_labeled_continue_outer.cx" />
```cx
let i;
i = 0
let hits;
hits = 0
'outer: loop {
    i = i + 1
    if i > 3 {
        break 'outer
    }
    loop {
        continue 'outer
    }
    hits = hits + 1
}
print(i)
print(hits)
```

## Continue

`continue` works in the interpreter. JIT coverage is partial.

<SourceComment source="origin/submain:src/tests/verification_matrix/t107_continue_in_func.cx" />
```cx
fnc: print_odds(n: t64) {
    for i in 0..n {
        if (i % 2) == 0 {
            continue
        }
        print(i)
    }
}
print_odds(6)
```

## When

`when` works in the interpreter. It lowers to the JIT for literal, range, definite-bool, and enum-variant patterns.

<SourceComment source="origin/submain:examples/tbool_uncertainty.cx" />
```cx
let y;
y = ?

when y {
    true    => print("is true"),
    false   => print("is false"),
    unknown => print("is unknown"),
}
```

This example assigns an actual unknown value (`?`) before matching it. Matching a definite `true` / `false` value lowers to the JIT even when an `unknown` arm is present and unreached, but matching a value that is actually unknown at runtime does not yet lower — this specific sample does not run under `--backend=cranelift` today.
